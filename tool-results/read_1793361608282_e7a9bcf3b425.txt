   344→- **M8 — secret-check self-match resolved**: the check command was documented verbatim in
   345→  this file, so every staged diff matched its own regex text (`sk` + dash inside the
   346→  documented pattern). Rewritten with bracketed separators (see Environment above); the ONE
   347→  remaining match in the M8 commit is the removed old line (`-` side of the diff) — no real
   348→  key material was ever staged (the two literal key patterns from the continuation prompt
   349→  were grep-verified absent before pushing). Future checks run clean.
   350→- **M8 — turn ordering in confirmatory grading**: `gradeAndApplyProbes` maps probe contexts
   351→  to answers by walking turns ordered `(createdAt asc, id asc)`; if several turns share a
   352→  timestamp the order falls to cuid ids. Tests MUST advance `now` per turn (the live clock
   353→  differs naturally). Use distinct `now` per `runConfirmatoryTurn` call.
   354→- **M8 — analyst mock shape**: a fake `analyze` returning `EvidenceItem[][]` where
   355→  `EvidenceItem[]` is expected fails at the writer with `skill: undefined` (Prisma
   356→  validation), not a TS error at the mock — the per-call script helper
   357→  (`analystScript(script: EvidenceItem[][])`) is the pattern to copy.
   358→- **M8 — revocation needs maintenance probes to ignore `openGap`**: a failed maintenance
   359→  probe always lands the mastered card in Relearning (Again) and mastered nodes are never
   360→  re-practiced, so gating maintenance probes on `fsrsState === 'Relearning'` would make the
   361→  §A6 revocation path unreachable. `probeEligible` gates CONFIRMATION probes on openGap,
   362→  MAINTENANCE probes only on the card schedule + 7d retry + hint gate.
   363→- **M7 — calling dynamic route handlers directly in tests**: the handler signature is
   364→  `(req, ctx)` where `ctx.params` is a Promise. Passing the cookie as the 2nd arg (instead
   365→  of into the Request headers) silently yields 401 (the request lacks the cookie). Use
   366→  `handler(jsonReq(url, body, cookie), { params: Promise.resolve({ id }) })`.
   367→- **M7 — planting a node with error-tracking history keeps `learning`**: `approveSeed`
   368→  uses upsert `update:{}` on purpose (§B5 never overwrites practiced state). Only the
   369→  skills WITHOUT history get a fresh `available` state. Tests + UI must not expect a node
   370→  that already produced confident errors to flip to `available`.
   371→- **M7 — user-generated GraphNodes are NOT FK-owned by users**: `ownerId` is a soft
   372→  reference; deleting a user does not delete their created nodes (by design — nodes feed
   373→  the shared world later). Test teardowns must delete them explicitly. The idempotency
   374→  test's mirror invariant is world-scoped (`isUserGenerated:false`) for the same reason.
   375→- **M6 — stale Prisma client after `prisma db push`**: a RUNNING dev server keeps the old
   376→  generated client in its require cache → new schema fields (e.g. NodePosition.pinned)

   378→  dev server via `setsid bash .zscripts/dev.sh > /tmp/devsh.log 2>&1 < /dev/null & disown`
   379→  (the harness's own entry: bun install → db:push → bun run dev → disown). Plain `nohup bun
